# 株スイング 設計メモ

## 全体の流れ

```
ブラウザ（/stocks 配下の画面）
   │  fetch（キーは持たない）
   ▼
API Route（app/api/stocks/*）── サーバー側だけでキーを使う
   ├─ J-Quants V2（x-api-key）… 銘柄情報・日足・決算サマリー
   ├─ Claude API … 開示スコア（匿名化した比率だけを渡す）
   └─ 保存先：Supabase（service_role）または .data/（ローカル）
```

## 画面

| 画面 | パス | できること |
|---|---|---|
| 銘柄分析 | /stocks | コード入力 → 日足・25/75日線・トレンド判定、決算の比較数値、Claude 採点、検証ログに記録、40万円での株数の目安 |
| バックテスト | /stocks/backtest | ① データ取得 ② 未採点の開示をまとめて採点 ③ ルールで実行。スコア帯別・トレンド別の成績、資金推移、取引一覧、実行結果の保存 |
| 検証ログ | /stocks/log | 記録したトレードを最新の日足で更新（翌営業日寄り付きで買い→損切り・利確・期限） |

## API Route

| メソッド・パス | 内容 | 外部への問い合わせ |
|---|---|---|
| GET /api/stocks/status | キーの有無・プラン・保存先 | なし |
| POST /api/stocks/prepare `{code, force?}` | 銘柄情報・日足・決算を取得して保存（半日以内は再取得しない） | J-Quants 最大4回 |
| GET /api/stocks/[code] | 保存済みの日足・トレンド・開示（比較数値とスコア付き） | なし |
| POST /api/stocks/score `{disclosureId, text?, force?}` | 開示を Claude で採点して保存 | Claude 1回 |
| POST /api/stocks/backtest `{codes, params, save?}` | 保存済みデータでバックテスト | なし |
| GET /api/stocks/backtest | 保存した実行結果の一覧 | なし |
| GET/POST/PATCH/DELETE /api/stocks/paper | 検証ログの一覧・記録・更新・削除 | PATCH で J-Quants（日足） |

## テーブル（supabase/migrations/001_stock_swing.sql）

| テーブル | 内容 |
|---|---|
| stocks | 銘柄マスタ |
| price_bars | 日足（生値と調整後値、売買代金） |
| disclosures | 決算サマリーの行（raw に J-Quants の1行を丸ごと） |
| disclosure_scores | Claude のスコア。モデルとプロンプトの版ごとに別の行。本文を読ませたかどうか（used_text） |
| backtest_runs / backtest_trades | バックテストの条件・成績・取引 |
| paper_trades | 検証ログ |
| fetch_log | いつ取得したか（再取得を減らす） |

RLS は有効化のみでポリシーなし。anon キーでは読み書きできず、サーバーの service_role だけが使えます。

## バックテストのルール（先読みを防ぐための決めごと）

- 買い：開示日の**翌営業日の寄り付き**（開示時刻が場中でも同じ。保守的）
- トレンド：開示日（以前で最後の営業日）の**終値**で判定。上昇＝終値＞25日線＞75日線
- 手仕舞い：損切り（買値−stop%）／利確（買値＋stop%×倍率）／N 営業日目の大引け
- 同じ日に損切りと利確の両方に届いたら**損切りが先**。寄り付きで飛び越えたら寄り付き値
- 売買とも滑りを不利な方向に加算。価格は分割などを反映した**調整後価格**
- 株数：資金×許容損失 ÷（買値×stop%）を 100株単位（または1株単位）で切り捨て。買えない場合は「見送り」として件数を表示
- 同じ銘柄の重複保有なし。保有中の分は資金から引いて、足りなければ見送り

## 開示スコアの匿名化

過去の開示を採点するとき、Claude が学習データでその後の株価を知っていると、バックテストが実力以上に良く見えます。
そのため Claude には**比率だけ**（前年同期比、予想修正率、来期予想の伸び、進捗率、利益率）を渡し、
会社名・コード・日付・金額は渡しません。短信本文を貼り付けて採点した場合は `used_text=true` として保存し、バックテストでは使いません。

## 既知の制約

- J-Quants の決算サマリーは数値のみ。短信の文章（定性情報）は含まれない
- 無料プラン：12週間遅れ・約2年分。1銘柄の開示は約8件なので、銘柄数を増やさないと取引回数が足りない
- 業績予想がレンジ形式の会社は、予想の値が収録されない（J-Quants の仕様）
- 配当の権利落ちは価格調整に含まれない（調整後価格は分割などのみ）
- 手数料・税金は「手数料（円）」の設定以外は考慮していない
